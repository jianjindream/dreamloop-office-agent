# 工作成果存储与恢复

## 默认本地模式

无需外部数据库。`app.storage.backend=h2`，`app.storage.directory=data/workspace`。

- `workspace.mv.db`：文档、不可变历史正文版本、状态、元数据、会话及完整消息。
- `attachments/`：按服务端生成的随机标识存储原始文件。文件不在 Web 静态目录内，下载必须通过文档授权接口。
- 浏览器：按服务地址、工作区和服务端确认的用户 ID 缓存会话及备份当前编辑草稿；缓存不替代服务端历史。

`APP_STORAGE_DIRECTORY` 可指定持久化目录。目录不可写、数据库不可访问时会明确报错；不会显示保存成功后实际只存在内存。备份时先停止应用，完整复制该目录；恢复时停止应用并完整恢复目录，数据库和附件须配套。

本地文件数据库适用于单实例。多实例请使用 PostgreSQL，并配置共享附件存储目录；当前附件适配器是文件系统，不包含对象存储适配器。

## PostgreSQL 模式

设置 `APP_STORAGE_BACKEND=postgres`，复用已有 `APP_POSTGRES_HOST/PORT/DATABASE/USER/PASSWORD`。工作成果连接池独立于检索基础设施的共享连接。

新增表 `office_documents`、`office_document_versions`，复用 `chat_sessions`、`chat_history`。建表幂等，文档追加版本、聊天写入/迁移/删除使用事务。

数据库不可用时不会自动切回本地数据库，避免两份数据各自写入。切换 backend 不会自动搬迁两边数据；已有 PostgreSQL 会话的部署应保持 `postgres` 模式，不要在不迁移的情况下改成 H2。旧版本文档只存在进程内存，没有可恢复的历史磁盘数据。

PostgreSQL 使用数据库备份工具，并同时备份 `attachments/`。Docker Compose 已使用 PostgreSQL，给 `/app/data/workspace` 挂载 `workspace_data` 卷；重建容器保留附件。`docker compose down -v` 会删除持久卷，不能用于保留数据的升级。

RAG、用户偏好、摘要及评测原有基础设施策略未改为 H2；工作成果文件数据库不等同于完整检索基础设施。重启后如使用仅在内存中的索引，需要在文档画布点击“建立索引”。

## 草稿、版本与回收站

文档画布编辑停止两秒后自动保存，手动保存将草稿标记为正式文档。每次成功保存追加版本；失败时保留当前正文和浏览器备份，不自动无限重试。

浏览器备份在“AI 文档”页提供恢复入口。恢复旧草稿后保存会提交 `base_version`；如果其他浏览器已更新该文档，返回冲突，用户核对正文后再保存，不覆盖服务端新版本。

删除文档进入回收站；恢复保留正文、历史和原始附件。恢复本身不触发外部索引操作，可单独重建索引。当前不提供永久清空回收站。

正文保存和知识库索引分开显示。索引失败可重试，不需要重复上传或创建正文版本。

## 会话历史与旧数据迁移

正常使用从服务端读取会话和逐页读取完整消息。更换浏览器时必须使用同一服务端身份：开发模式可配置相同 `VITE_USER_ID`、`VITE_WORKSPACE_ID`；默认匿名浏览器会生成不同用户 ID，不会自动识别为同一个人。生产环境使用映射到相同用户/工作区的凭据。

旧键 `dreamloop-chat-sessions-v2` 仅用于迁移和原始备份。可核实旧浏览器用户 ID 与当前用户一致、且位于默认工作区时自动迁移；其他情况由用户在“迁移此浏览器旧对话”入口确认导入当前身份。每个会话事务导入，服务端已有记录优先，重复导入不会重复追加消息。

全部迁移成功才记录当前身份的迁移完成标记；失败保留原始键和重试入口。成功删除的服务端会话不会因为浏览器 v3 缓存而被重新导入。旧浏览器原始备份不会自动删除。
