# 项目周报首版：范围与验收

状态：产品基线。第一批交付存储、会话和验收资料；周报任务入口、附件精确引用和导出分别在第二、三批实现。

## 目标用户与价值

面向项目负责人和知识工作者。把项目记录、会议纪要及上期周报整理为可核实、可编辑、可交付的本期周报，减少资料核对和排版时间。

## 固定流程

1. 选择项目、汇报起止日期、公司模板与资料范围。
2. 上传或选择项目记录、会议纪要、上期周报；明确哪些资料实际参与处理。
3. 提取完成事项、进行中事项、风险、指标、负责人和下一步计划。
4. 核对来源、时间范围与数字；集中提示缺项和资料冲突。
5. 生成草稿，查看引用，补充信息和修改正文。
6. 确认保存并导出 Word/PDF；行动项由用户确认后保存为待办。

## 输入契约

- 项目名称、汇报周期、资料列表、输出模板必填。
- 资料保留原始文件、来源、版本与上传时间；文件名不作为唯一标识。
- 资料中的事实与用户补充的信息分别标注来源。
- 第三批前允许使用 Markdown/TXT 测试输入；DOCX、XLSX、导出均不算第一批已完成功能。

## 输出契约

使用 [周报模板](fixtures/template.md)：摘要、本周完成、进行中事项、风险与阻塞、下周计划、待确认信息及来源。

- 完成事项须属于本期，不能把上期成果再次记为本周完成。
- 区分已完成、计划完成、尚待确认；不猜测预算、负责人、日期和完成率。
- 同一指标有冲突时同时列出资料值和版本，不擅自选择。
- 所有数值计算保留口径、输入与计算结果；缺失值不作为零处理。
- 用户可修改；保存和索引是两个独立状态，索引失败不代表正文丢失。

## 第一批验收清单

- [x] 文档、不可变历史版本、元数据、原始附件在重启后仍可读取。
- [x] 自动保存以提交时正文为准，不覆盖保存期间继续输入的内容；浏览器关闭前备份本机草稿。
- [x] 旧版本草稿提交到已更新文档时返回冲突，保留用户正文。
- [x] 文档删除进入回收站，恢复后正文、历史和原始附件仍在，检索索引可单独重建。
- [x] 索引失败时明确返回“正文已保存”，允许重试索引。
- [x] 会话以服务端为准，换浏览器使用相同身份能读取；浏览器缓存按身份和工作区隔离。
- [x] 超过 500 条的会话能逐页读取，模型上下文摘要不删除产品历史。
- [x] 会话可以搜索正文、重命名和删除；删除失败时不移除页面记录。
- [x] 旧浏览器会话幂等迁移；失败后原始记录保留；已存在的服务端会话优先。
- [x] 未获授权的用户不能读取、恢复或下载其他工作区用户的文档和会话。

## 后续批次边界

第二批：附件和提问绑定、资料范围约束、办公意图路由、原文引用定位。

第三批：DOCX/XLSX 输入、确定性计算、审阅差异、公司模板、Word/PDF 导出和完整周报任务。

第四批：后台任务中心、办公平台连接、团队权限完善与真实用户试点。

首版不承担自动发邮件、财务审批或实时会议转写。试点观察每份周报完成时间、修改量、事实错误和次周复用率。
